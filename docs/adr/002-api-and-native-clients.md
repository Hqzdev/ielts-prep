# ADR 002: общий API для веба, iOS и macOS

Дата: 2026-09-06. Статус: принято.

## Контракт

Источник схем — `packages/contracts/src`. `api.ts` задаёт операции, входы, ответы и семантику повторов. Генератор создаёт OpenAPI 3.1 и типы SDK. HTTP-адаптеры применяют те же входные схемы; интеграционные тесты проверяют реальные ответы по контракту. Web SDK использует `/api/v1`. Старые `/api`-пути временно переэкспортируют те же обработчики для совместимости.

Пакет api-client не знает о React и браузерном хранилище. `accessToken` вызывается заново для каждого запроса. Middleware сохраняет HTTP-код, стабильный код ошибки и `X-Request-ID`. Автоматического повтора POST/PATCH нет.

| Операция                                          | Повтор после сетевой ошибки                                                                    |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Получение данных                                  | Повторить GET с актуальной сессией                                                             |
| Черновик                                          | Прочитать текущую ревизию; при конфликте предложить восстановление локальной копии             |
| Submit, завершение quiz/round                     | Использовать прежний ID; повтор возвращает сохранённый результат                               |
| Сохранение слова                                  | Повторить желаемое значение saved                                                              |
| Создание quiz, round, upload-ticket или сообщения | Не повторять вслепую; сохранить ID успешного ответа, сверить историю                           |
| Retry assistant                                   | Передать прежний `retryAssistantId`; сервер захватывает только доступное для повтора сообщение |

UTC-моменты передаются как ISO 8601. Учебный день — `YYYY-MM-DD` в IANA timezone профиля. Несколько подходящих занятий в один локальный день дают один огонёк. Изменение timezone не переписывает исторические дни.

## Аутентификация

Веб использует существующую Supabase SSR cookie-сессию. Native передаёт `Authorization: Bearer <access_token>`. Сервер проверяет токен через Supabase Auth, затем читает профиль и применяет общую политику доступа. Наличие некорректного Authorization не приводит к fallback на cookie другого пользователя. На каждом запросе проверяются membership, роль и владение объектом.

Будущий Apple-клиент получает сессию через OAuth PKCE, системный authentication session и зарегистрированный callback/deep link. Refresh token хранится в Keychain. Обновление сессии нужно сериализовать, чтобы параллельные запросы не вращали refresh token одновременно. При выходе отзывается refresh session и очищается Keychain. Уже выданный JWT может оставаться действительным до истечения; отзыв membership действует через серверную проверку профиля. Политика немедленного отзыва отдельных сессий потребует отдельного решения.

## Потоки и аудио

Чат возвращает `application/x-ndjson`: thread, expression, token, error, done. HTTP 200 означает открытие потока, а конечный результат сообщает событие done. Отключение клиентского чтения не отменяет сохранение ответа на сервере; при восстановлении клиент читает историю принадлежащего ему потока.

Транскрипция принимает бинарный `audio/wav`, mono PCM, 16 kHz, 0.3–60 секунд, с UUID thread в query. Speaking-запись сначала получает upload-ticket, загружается по подписанному разрешению в закрытый Storage, затем подтверждается через complete. Воспроизведение использует короткоживущую signed URL. Сервисные ключи и таблицы ответов не передаются приложениям.

## Совместимость Swift

`pnpm swift:check` генерирует все операции официальным Apple Swift OpenAPI Generator и компилирует клиент с Runtime/URLSession. Дополнительно декодируются ошибка, nullable-результат quiz, дизайн-токены и позы Вея. `Package.resolved` закрепляет транзитивные зависимости. Nullable-схемы используют стандартный JSON Schema type union, чтобы Swift сохранял Optional без пропуска ветки null.

Будущие `apps/ios` и `apps/macos` получат отдельные SwiftUI-интерфейсы. Общие Swift-пакеты будут отвечать за API, сессию, синхронизацию и дизайн. React, DOM, IndexedDB и Web Audio в Swift не переносятся. Бизнес-истина остаётся на сервере; локальная очередь черновиков соблюдает версии и дедлайны API.
