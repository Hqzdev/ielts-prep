# ADR 003: слои нативных приложений

Дата: 2026-09-07. Статус: принято.

## Решение

`apps/Veylo.xcworkspace` объединяет независимые проекты `apps/ios/Veylo.xcodeproj` и `apps/macos/Veylo.xcodeproj`. Схемы `Veylo iOS` и `Veylo macOS` собирают по одному приложению. Исходники, ресурсы и bundle ID разделены по платформам. Минимальные версии iOS и macOS 27.0 сохранены из исходного проекта. Поддержка visionOS исключена.

В каждом приложении действует направление Interfaces → Application → Domain. Domain содержит чистые сущности и правила. Application содержит сценарии и протоколы требуемых сервисов. Infrastructure реализует эти протоколы, используя API, Keychain, локальное хранилище и аудио. Composition создаёт реализации, внедряет зависимости и запускает интерфейс.

SwiftUI располагается в Interfaces и точке входа Composition. Domain и Application не зависят от UI, сетевых клиентов, хранилищ и платформенных глобальных объектов. Views не создают адаптеры и не обращаются к сети или хранилищу напрямую. Зависимости передаются через инициализаторы; композиция предпочтительнее наследования.

## Текущее состояние

В iOS реализован интерактивный локальный прототип: Domain содержит модели опроса и упражнений, Application — сценарии онбординга и демосессий, Infrastructure — демонстрационный контент и локальное сохранение. Interfaces содержит SwiftUI-экраны и навигацию, Composition внедряет реализации. В macOS сохранён исходный стартовый экран. Документация об ответственности слоёв исключена из сборок приложений. Пустые типы и неиспользуемые адаптеры не создаются.

Слои находятся в одном target каждой платформы. Границы закреплены структурой и правилами AGENTS.md, но не изолированы компилятором. Отдельные Swift-модули и общие пакеты вводятся при появлении реальных зависимостей и повторного использования. Файлы соседней платформы напрямую не подключаются.

Бизнес-истина остаётся на сервере; правила API и аутентификации определяет [ADR 002](002-api-and-native-clients.md).

## Проверка

Обе схемы должны собираться из workspace, каждая только для своей платформы. При добавлении сценариев проверяются их поведение и зависимости между слоями. Документация слоёв не должна попадать в ресурсы приложения.
