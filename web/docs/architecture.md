# Архитектура IELTS Prep

## Границы

Один Next.js-проект и одна PostgreSQL-база. React-компоненты отвечают за интерфейс, классы сценариев — за правила приложения, репозитории — за доступ к данным. Внешние вызовы изолированы в GeminiProvider, AudioService и Workflow. Python не требуется для работы сайта.

| Область | Файлы | Ответственность |
|---|---|---|
| Identity | `server/identity.ts`, `server/supabase.ts`, `app/auth`, `app/api/invitations` | Подтверждённая сессия, роль, приглашение, доступ к бете |
| Catalog | `repositories/catalog.ts`, `services/content-import.ts` | Опубликованная версия, фильтры, личный статус, закрытые ключи |
| Practice | `services/practice.ts`, `repositories/practice.ts`, `client/draft-session.ts` | Версии черновика, таймер, сдача, исправление |
| Assessment | `workflows/assessment.ts`, `grade-validator.ts`, `services/gemini.ts` | Очередь, рубрика, цитаты, оценки, структурный контроль |
| Speaking | `client/voice.ts`, `services/audio.ts` | MediaRecorder, VAD, WAV, озвучка, доступ к аудио |
| Learning | `domain/planner.ts`, `domain/statistics.ts`, `services/learning.ts` | Недельный план, независимые работы, повторяющиеся ошибки |
| Vocabulary | `services/vocabulary.ts`, `word-assistance.ts` | Слова, закрытые ключи тестов, частота повторения |

| Tutor | `services/tutor.ts` | Контекст ученика, поток ответа, история, лимиты |

## Данные и транзакции

`tasks` указывает на текущую опубликованную запись `task_versions`. Попытка хранит версию и полный снимок задания, поэтому обновление каталога не меняет уже выполненную работу. `reading_keys` хранится отдельно, без прав чтения у браузерных ролей.

`attempts` хранит владельца, ответ, режим, дедлайн, время, ревизию и ссылку на исходную попытку. Состояния: `in_progress`, `paused`, `submitted`, `completed`. Состояние проверки независимо: `unavailable`, `queued`, `processing`, `ready`, `failed`, `insufficient_evidence`.

Создание, сохранение, сдача, повторная проверка, импорт, принятие приглашения и результат словарного теста выполняются PostgreSQL-функциями. Адресуемая строка блокируется; сдача и запись задания на обработку происходят в одной транзакции. Повторная сдача возвращает тот же assessment. Конфликт черновика возвращает 409 с кодом `REVISION_CONFLICT`.

Строгий дедлайн задаёт сервер. После дедлайна изменения отклоняются; результат строится по последнему серверному ответу. Локальная копия не продлевает время. Тренировочные черновики сохраняются через 800 мс после ввода и каждые четыре секунды при изменениях. IndexedDB хранит дополнительную копию и незагруженное аудио.

Исправление создаёт новую попытку. Исходный ответ и результат остаются неизменными. Повторные попытки исключены из основной динамики; доступно сравнение до/после.

## Проверка

ReadingGrader учитывает набор вариантов, частичные баллы multiple choice, ограничения слов, число, регистр, пробелы и допустимые ответы из ключа. ReadingBandCalculator рассчитывает учебный band вместе с набранными баллами и процентом. Для коротких упражнений `round(earned / possible × 40)` даёт эквивалент баллов из 40; затем применяется таблица Academic. Количество баллов учитывает каждый верный вариант multiple choice, а не только число вопросов. Интерфейс обозначает оценку как Estimated band. Шкала и ограничения описаны в [Reading practice bands](reading-bands.md).

Writing и Speaking ставятся в `assessment_jobs`. Диспетчер берёт записи с временной арендой. Ошибка запуска не удаляет задание. Workflow резервирует token на assessment, что предотвращает параллельный запуск одинаковой проверки. Временная ошибка повторяется максимум три раза суммарно; ошибки ключа, модели и структуры считаются конечными. Обнаруженное прерванное выполнение переводится в техническую ошибку с возможностью явного повторного запуска.

GeminiProvider возвращает структурированные данные. GradeValidator проверяет критерии, диапазон, точные цитаты, требования карточки и границы аудиофрагментов. Нечитаемый JSON либо ошибочная структура допускает одну попытку исправления. Сервер самостоятельно усредняет четыре критерия и округляет до 0,5.

Расшифровка и оценка Speaking — два отдельных запроса. Проверяющий получает и исходное аудио, и расшифровку. Недостаток материала не превращается в нулевой балл. Для объяснения чисел Task 1 используется тот же набор данных, который отрисован графиком.

## Аудио

Браузер записывает ответ, декодирует его через Web Audio и преобразует в WAV PCM, mono, 16 kHz. Запись вопроса и пользовательская запись разделены. Подписанное разрешение выдаётся только владельцу активной попытки. Сервер проверяет размер, заголовок WAV, частоту и длительность перед пометкой `ready`.

Файлы лежат в закрытом bucket `speaking`; ссылки воспроизведения действуют пять минут. Срок хранения — 30 дней, досрочное удаление доступно из кабинета. Расшифровка и разбор сохраняются отдельно. Gemini получает inline-аудио, поэтому временные объекты Gemini Files не создаются. Озвучка готового вопроса кэшируется в `examiner` по тексту, модели и голосу.

## Доступ и лимиты

Вход и право на участие в бете проверяются независимо. Подтверждённый email ещё не даёт доступ к заданиям. Приглашение одноразовое, адресное, со сроком семь дней. Лимит участников проверяется под транзакционной блокировкой и передаётся только доверенным сервером.

Личные таблицы защищены RLS. Серверные маршруты дополнительно проверяют владельца объекта. Сервисный ключ и ключ Gemini никогда не передаются клиенту. Импорт, публикация и приглашения доступны администратору. Начальные лимиты: пять проверок в сутки, одна одновременно, 30 сообщений/запросов словарной помощи; календарные сутки лимита считаются по UTC.

Технические логи содержат идентификатор и код, без текста эссе, транскриптов или аудио. Флаги AI не заменяют калибровку, а позволяют закрыть оценивание до её завершения.

## Контент

Импорт валидирует 146 упражнений, ключи, доказательства, визуальные данные и диаграммы. Изменение создаёт новую версию; неизменный импорт не создаёт дубликаты. `used` исходного генератора не влияет на личную историю. Старый отдельный набор из 15 заданий не импортируется.

Для добавления контента администратор загружает JSON `{ "entries": [...] }`, где каждый элемент соответствует ContentEntry из `src/domain/task.ts`. Публикация возможна после валидации. Перед импортом нового материала необходимо проверить естественность текста и корректность объяснения, а не только наличие цитаты.

## Учебный план

План создаётся на неделю в часовом поясе ученика и хранится в базе. До достаточной истории навыки чередуются; после пяти оценённых независимых работ увеличивается частота слабого навыка, Reading учитывает тип вопроса. Длинный Writing разбивается на продолжения одной попытки. Уже начатые и завершённые занятия сохраняют положение. Пропущенное можно перенести вручную.

Изменение расписания применяется при построении следующего недельного плана. Текущая неделя остаётся стабильной. Точность статистических закономерностей ограничена объёмом реальных самостоятельных работ.
