# Форматы генератора

Это самостоятельные тренировочные материалы в формате IELTS, а не официальные вопросы, воспоминания участников или прогноз следующего экзамена. Ограничения длины промпта и количества вопросов внутри тренировочного сета — настройки генератора, а не дополнительные правила IELTS.

## Запуск

```bash
python3 -m pip install -r requirements.txt
python3 generate_tasks.py --count 8 --task writing_task2
```

Ключ `GEMINI_API_KEY` читается из `.env` рядом со скриптом. При необходимости там же можно задать `GEMINI_MODEL`. `tasks.json` тоже находится рядом со скриптом. Успешные задания добавляются и сохраняются сразу; прежние записи не переоцениваются и не изменяются. Прервать генерацию можно через Ctrl+C.

Цикл типов и тем продолжается с учётом числа уже сохранённых заданий выбранного раздела. `--shuffle-start` меняет стартовую позицию. Последние задания передаются модели как примеры для исключения; близкие текстовые повторы отклоняются. Это уменьшает повторяемость, но не гарантирует смысловую уникальность.

## Writing Task 2

| Значение `task_type`       | Что требуется от кандидата                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| `opinion`                  | Оценить степень согласия с одной позицией                                                        |
| `discussion`               | Рассмотреть две позиции и выразить своё мнение                                                   |
| `advantages_disadvantages` | Рассмотреть преимущества и недостатки без отдельного требования outweigh                         |
| `outweigh`                 | Оценить, перевешивают ли преимущества недостатки                                                 |
| `causes_solutions`         | Объяснить причины проблемы и предложить меры                                                     |
| `problem_solution`         | Выделить проблемы, возникающие из ситуации, и способы их решения                                 |
| `two_part`                 | Ответить на два вопроса; здесь используется вариант «причины + последствия для указанной группы» |
| `positive_negative`        | Оценить изменение как положительное или отрицательное                                            |

Эти названия нужны для разнообразия тренировок. Они не означают, что существует ровно восемь официальных категорий: определяющее значение имеет конкретная формулировка вопроса. Основа — [разбор требований к Task 2 от IDP](https://ielts.idp.com/cyprus/about/news-and-articles/article-how-to-understand-task-2-writing-questions).

Темы разбиты на конкретные аспекты: например, не просто technology, а доступ к цифровым услугам или автоматизация повседневных сервисов. Контекст не должен подсказывать аргументы, навязывать ответ или требовать специальных знаний.

## Speaking

- `speaking_part1`: один бытовой тематический сет из 4–5 коротких персональных вопросов. Это не вся первая часть интервью.
- `speaking_part2`: вступление Describe, три опорных пункта, отдельный пункт с объяснением и 1–2 завершающих вопроса. Сохраняются структурные поля и собранный `cue_card`.
- `speaking_part3`: 5–6 вопросов, переходящих от темы карточки к более общему обсуждению. Если в файле есть карточки Part 2, используются они; иначе берётся конкретная тема из каталога. Связь записывается в `part2_anchor`.

Структура сверена с [описанием Speaking IELTS](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-speaking) и [официальными образцами](https://ielts.org/cdn/ielts-sample-tests/ielts-speaking-sample-tasks-2023.pdf).

## Writing Task 1 Academic

Поддерживаются `bar_chart`, `line_graph`, `pie_chart`, `table`, `process_diagram`. Числовые задания содержат заголовок, единицы, периоды/группы сравнения и серии данных. Код проверяет согласованность ключей, допустимость чисел, диапазон процентов и сумму 100% для каждого pie chart. Процессы описываются последовательными стадиями.

Графики и схемы пока не рисуются: `visual_status` имеет значение `not_rendered`. Без визуализации это спецификация задания, а не полностью готовая имитация экзамена. Карты и комбинированные графики не реализованы. Данные синтетические.

См. [официальное описание Academic Writing](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-writing).

## Reading

`reading_passage` создаёт один текст примерно на 750–850 слов в шести абзацах A–F и восемь утверждений TRUE/FALSE/NOT GIVEN. Это упражнение на один тип вопросов, не полноценная секция Reading.

Ответы находятся отдельно в `answer_key`, а не рядом с утверждениями в `questions`. Каждый ответ включает абзац, цитату из текста и объяснение. Для NOT GIVEN цитируется ближайший контекст и указывается отсутствующее сведение. Автоматически проверяются длина, нумерация, порядок абзацев и наличие цитаты. Правильность логического вывода и фактическая точность текста требуют редакторской проверки: совпадение цитаты само по себе их не доказывает.

Различие FALSE и NOT GIVEN и назначение формата сверены с [официальным описанием Academic Reading](https://ielts.org/take-a-test/test-types/ielts-academic-test/ielts-academic-format-reading).

## Проверки и расход запросов

Структуру результата задаёт JSON Schema; после ответа выполняются локальные проверки. Несоответствующее задание повторяется с описанием ошибки, максимум три попытки. Каждая попытка может расходовать отдельный запрос. Больший лимит токенов нужен для завершения JSON и особенно длинного Reading; это верхний предел, а не фиксированный расход на каждое задание.

При ошибке доступа, конфигурации или квоты API пакет останавливается. Значения лимитов зависят от проекта — см. [Google AI Studio](https://aistudio.google.com/). В старой SDK не используется несовместимый параметр `thinking_level`.
